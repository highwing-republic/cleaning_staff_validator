# 清掃勤務表作成アプリ

旅館・ホテルの清掃スタッフについて、通常勤務条件・勤務希望・予約状況・必要人数から
10〜14日程度の勤務表を作成する Streamlit アプリです。

勤務表は OR-Tools CP-SAT で自動作成し、画面上で手直し・固定・再生成・日ごとの確定を行い、
最後にブラウザから A4 横で印刷できます。Excel での保存にも対応しています。

> リポジトリ名は `cleaning_staff_validator` のままですが、
> アプリの役割は勤怠CSVの検証から勤務表の作成へ移っています。

## 運用の流れ（若女将向け）

```
スタッフ本人 → 紙で「普段と違う希望」だけ提出
若女将      → アプリへ転記 → 必要人数を確認
            → 勤務案を作成 → 必要な箇所を手直し → 配布用に確定
            → ブラウザから印刷して配布
当日        → 紙へ手書きで変更
```

普段はホームの **「勤務表をつくる」** から、次の4段階で進めます。

1. 作成する期間を選ぶ
2. 普段と違う休みの希望と、必要人数を確認して保存する
3. 勤務案を作成し、内容を確認して保存・手直しする
4. 配布用に確定し、印刷する

人数の初期値は平日6人・土日5人です。「基本設定」で変更でき、保存済みの日付の条件は維持されます。
スタッフの通常勤務条件は初回に登録します。予約室数・最大人数・役割別条件などは詳細操作で設定できます。
生成した案は「この案を保存して使う」を押すまで保存されません。
手直し時の「この勤務を自動作成で変えない」を有効にすると、作り直してもその勤務を維持します。

保存後にブラウザを閉じても、ホームの **「作成途中の勤務表を開く」** で再開できます。
確定済みの期間は **「完成した勤務表を見る・印刷する」** から開きます。
印刷画面が開かない環境では「印刷用ファイルを保存」から保存したファイルをブラウザで開けます。

従来の画面は「スタッフ設定」「詳細操作（必要なときだけ）」に残しています。

1. **スタッフ管理** — スタッフと通常の勤務条件（曜日・勤務時間・役割・総合スキル・特殊スキル）を確認する
2. **勤務希望** — 紙に書かれた「普段と違う希望」を転記する（絶対休み／できれば休み／早上がり／遅出／通常休みだが勤務可能）
3. **予約・必要人数** — 対象期間の予約室数と必要人数・最大人数・役割条件・スキル条件を入力する
4. **シフト生成** — 勤務案を自動作成し、下書きとして保存する
5. **勤務表調整** — 出勤／休みを手直しし、動かしたくない日を固定して再生成し、日ごとに確定する
6. **勤務表出力** — 人数・役割・スキルの不足を最終確認し、印刷用 Excel を出力する

左メニューの「補助機能（勤怠CSV）」には、以前からの **勤怠CSV取込** と **勤怠データ検証** が残っています。
こちらは勤怠システムから出した実績CSVを確認するための機能で、勤務表づくりには使いません。

## 実装済みの機能

- スタッフ管理（役割・総合スキル・通常勤務曜日・通常勤務時間・特殊スキル・目標勤務日数／週・最大連続勤務日数）
- 期間別の勤務希望（絶対休み／できれば休み／早上がり／遅出／通常休みだが勤務可能／備考）
- 予約室数・必要人数・最大人数・役割別必要人数・スキル条件の日別入力（CSV/Excel 取り込みにも対応）
- CP-SAT による勤務案の自動作成（最低必要人数・役割・スキル・最大連勤・勤務可能条件を考慮）
- 目標勤務日数と公平性を優先し、必要に応じて最低必要人数を上回る配置を許容
- 目標未設定のチェッカーは週5日、その他は最低必要人数の平均を自動目安として配置
- できれば休みの尊重と目標勤務日数／週への配分（多段最適化）
- 勤務案の下書き保存、手修正、固定、固定を守った再生成（反映前に変更内容を確認）
- 日ごとの確定・確定解除
- 保存済み勤務表の検証（人数不足・最大人数超過・役割不足・スキル不足・要件未設定・未作成・下書き）
- 印刷用 Excel 出力（勤務表／日別確認／問題一覧／出力情報、A4横・横1ページ、当日手書き用の備考欄つき）
- 補助機能: 勤怠CSV取込と勤怠データ検証（旧機能）

## 起動方法

Windows では、管理者による初回セットアップ後、**`start.cmd` をダブルクリック**するとブラウザで開きます。
起動したウィンドウは使用中に閉じないでください。終了時はそのウィンドウで Ctrl+C を押します。
この起動方法は同じPCからのみアクセスできます。
ほかのアプリが起動中の場合は、8501〜8510の空いている番号を自動で選びます。
ブラウザが開かない場合は、起動ウィンドウに表示されたURLを開いてください。

初回セットアップ（Windows / PowerShell）:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
streamlit run app.py
```

macOS / Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

データベースは既定で `data/app.db` に作られます。別の場所を使う場合は
環境変数 `CLEANING_STAFF_VALIDATOR_DB_PATH` にファイルパスを設定してください。

### Streamlit Community Cloud で使う場合（データの自動控え）

Streamlit Community Cloud は、再起動・スリープ・アプリの更新（マージ）のたびにサーバー内のファイルを消します。
そのままでは `data/app.db`（スタッフ登録など）も消えるため、GitHub の**非公開**リポジトリへ自動で控えます。

- 起動直後、サーバーにデータベースが無ければ、控えから戻します。
- 保存などで内容が変わるたびに、控えを更新します（1回の更新が控え用リポジトリの1コミットになり、過去の状態に戻すこともできます）。
- 控えを読めないときは、その場で何回か読み直します。それでも読めなければ、保存先のデータを空のデータで上書きしないよう控えを止め、
  読み込めるまで画面を止めて「もう一度読み込む」ボタンだけを出します（空の画面で入力させないため）。
- 設定が無いとき（PC の `start.cmd` など）は何もしません。

設定手順（管理者が一度だけ行う）:

1. GitHub で**非公開（Private）**の空のリポジトリを作る（例 `cleaning-staff-data`）。
   スタッフ名などの個人情報が入るため、必ず Private にします。アプリ本体のリポジトリとは別にします。
2. GitHub の Settings → Developer settings → Personal access tokens → **Fine-grained tokens** でトークンを作る。
   - Repository access: **Only select repositories** で 1. のリポジトリだけを選ぶ
   - Permissions: **Contents** を **Read and write**（ほかは不要）
   - 有効期限が切れると控えられなくなるため、期限を控えておき、切れる前に作り直す
3. Streamlit Community Cloud のアプリの **Settings → Secrets** に次を貼り付けて保存する（トークンは GitHub 以外に貼らない）。

```toml
[data_backup]
repo = "highwing-republic/cleaning-staff-data"
token = "github_pat_..."
# branch = "main"   # 省略時は既定ブランチ
# path = "app.db"   # 省略時は app.db
```

設定が効いていると、左メニューの下に「入力した内容は自動で保存先に控えています」と表示されます。
控えの状態は、Streamlit Cloud の「Manage app」のログに `data backup:` で始まる行として出ます（トークンは出力しません）。
例: `data backup: restored 172032 bytes from …`（戻せた）、`data backup: restore failed (attempt 1/3): …`（読めなかった理由）、
`data backup: settings [data_backup] not found; backup is off`（Secrets が読めていない）。

## 運用上の注意

- 当日変更は印刷した勤務表へ手書きで対応し、アプリ上の勤務表は前日までの計画表として扱います。
  当日の実績をアプリへ戻す機能はありません。
- 本番利用前・大きな変更前には `data/app.db` をバックアップしてください
  （PC版に自動バックアップはありません。Streamlit Cloud では上記の自動控えを設定できます）。
- 予約室数から必要人数は自動計算しません。必要人数は若女将が判断して入力します。
- 1人で使う前提です（複数人の同時編集・ログイン認証はありません）。
- かんたん作成では、生成後に入力や勤務表が変わった場合、古い案の保存を拒否します。
  詳細操作を含めた複数人運用を保証するものではありません。
- 保存先はローカルのSQLiteです。再開できるのは、このデータが保持されている場合です。
  Streamlit Cloud では上記の自動控えを設定してください（1つのアプリから使う前提で、
  同じ控えを複数のアプリから同時に使うことは想定していません）。
- 納品用のWeb公開・ID/パスワード認証は今回の変更に含みません。
  顧客所有の公開環境、永続DB、バックアップ、認証を別途整備する必要があります。
